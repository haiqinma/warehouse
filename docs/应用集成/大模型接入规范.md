# 大模型接入规范

本文定义 Warehouse 面向 Chat、Agent、Knowledge 等大模型应用的接入边界。Warehouse 是用户第一手资料的存储与管理底座；模型只能通过受控 API 访问资料，不能绕过认证、授权和审计。

## 接入层次

```text
模型 / Agent
    ↓
Tool 或 MCP 适配层（规划能力）
    ↓
Warehouse HTTP/OpenAPI、WebDAV、S3
    ↓
资料对象、目录、版本与元数据
```

Tool 是可执行的业务能力，MCP 是发现、描述和调用 Tool 的协议。MCP 适配层不得实现独立的权限判断，也不得直接访问存储目录。

## 当前可用接口

- 机器可读的 JSON API：见 [OpenAPI 契约](./OpenAPI/warehouse.openapi.yaml)。
- 文件协议：见 [WebDAV 请求链路](./WebDAV请求链路.md) 和 [S3 协议](./S3协议.md)。
- Knowledge 接入约定：见 [Knowledge 数据接入](./Knowledge数据接入.md)。

新增或修改 JSON API 时，必须同步更新 OpenAPI 和生成的客户端类型。

## Tool 定义要求

未来向模型暴露 Warehouse 能力时，每个 Tool 至少包含以下元数据：

```json
{
  "name": "warehouse.object.read",
  "description": "读取用户有权访问的资料对象",
  "inputSchema": {},
  "outputSchema": {},
  "requiredScopes": ["object:read"],
  "sideEffects": "none",
  "idempotency": "safe",
  "confirmationRequired": false
}
```

Tool 名称和版本必须稳定；输入输出使用明确的 JSON Schema；写入、删除、移动、分享和权限变更属于有副作用操作，默认需要更严格授权，必要时要求用户确认。

## 调用上下文与安全

每次调用都必须能够追踪用户或服务主体、授权范围、资源范围、`requestId` 和 `traceId`。适配层应复用 Warehouse 现有认证与权限检查，并记录调用者、Tool 版本、资源、结果、耗时及拒绝原因。

不得向模型或第三方 Tool 传递用户主密码、钱包私钥或全局管理员密钥。访问凭证应短期、可撤销且范围受限。

## 长任务约定

大文件上传、批量导入或其他不可在单次请求内完成的操作，应采用异步任务：返回 `taskId` 或 `runId`，提供状态、进度、取消、重试和幂等键。任务结果应能关联原始请求和审计记录。

## 实施顺序

1. 稳定 HTTP/OpenAPI 的资源模型、错误结构和权限语义。
2. 为对象查询、目录浏览、受控读取建立只读 Tool。
3. 在不绕过业务 API 的前提下，为高频场景增加 MCP Server。
4. 再开放写入等有副作用 Tool，并补充确认、配额和审计策略。

本文中的 Tool/MCP 适配层属于演进方向；未在代码和 OpenAPI 中出现的能力，不应视为当前已提供的接口。
