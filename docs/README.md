# Warehouse 文档

本目录只保留用户接入、当前架构、下一版架构、多副本、部署运维、协议/API 和少量专项方案。架构文档按版本递增维护：已实现写入 `仓库架构V1.md`，下一阶段必须优先落地的能力写入 `仓库架构V2.md`，V2 稳定后的平台化能力写入 `仓库架构V3.md`。

快速开始：[README.md](../README.md)

## 文档入口

### 架构版本

- [仓库架构V1.md](./仓库架构V1.md)：当前已实现架构，包含模块、请求链路、资产空间、分享、回收站、配额和多副本基础
- [仓库架构V2.md](./仓库架构V2.md)：下一阶段必须优先落地的能力，包含 Knowledge 数据源边界、reconcile 自愈、复制观测、限流、generation 清理、quota 运维基础版和系统对象治理
- [仓库架构V3.md](./仓库架构V3.md)：V2 稳定后的平台化能力，包含正式多副本、状态外置、自动编排、运维 CLI 平台化、quota 产品化和性能扩展
- [多副本方案.md](./多副本方案.md)：合并 active/standby、internal 复制、容灾和多副本路线的唯一设计入口

## 文档收敛口径

- 架构只保留 `仓库架构V1.md`、`仓库架构V2.md`、`仓库架构V3.md` 这种版本化文档。
- 多副本只保留 `多副本方案.md` 一个设计入口。
- 操作文档只保留在 `部署手册.md`。

## 维护规则

- 已经实现的架构事实只写入 `仓库架构V1.md`。
- 下一阶段必须优先落地的架构目标写入 `仓库架构V2.md`；V2 稳定后的平台化能力写入 `仓库架构V3.md`；后续按 `V4` 递增。
- 多副本相关只维护 `多副本方案.md` 一个设计入口。
- 部署、升级、回滚、切换和排障只维护在 `部署手册.md`。
- 架构和方案文档优先用图、表、流程图说明，不直接贴源码。
- OpenAPI 变化必须同步更新 [Warehouse OpenAPI](./openapi/README.md) 和 `openapi/warehouse.openapi.yaml`。
