# Warehouse 产品文档

本文档体系以“理解产品、理解架构、接入产品、运行产品、追溯决策”为主线组织。目录名称表达产品视图，文件名称表达稳定主题。

## 文档地图

```text
docs/
├── 产品概览/                  # 产品定位、边界、用户使用
├── 产品架构/
│   ├── 架构演进/              # V1 基础事实、V2 当前事实、V3 后续规划
│   └── 能力设计/              # 认证、资产、共享、配额、高可用
├── 应用集成/                # WebDAV、S3、Knowledge、OpenAPI
└── 运维部署/                  # 安装、配置、升级、切换、排障
```

## 推荐阅读路径

1. 先读[产品定位](./产品概览/产品定位.md)。
2. 再读[系统架构-V2](./产品架构/架构演进/系统架构-V2.md)；需要历史或规划时阅读 V1/V3。
3. 按场景阅读[能力设计](./产品架构/能力设计/)或[应用集成](./应用集成/)。
4. 部署、升级看[部署手册](./运维部署/部署手册.md)；运行、切换和排障看[运维手册](./运维部署/运维手册.md)。

## 命名与维护规则

- 产品概览回答“是什么、服务谁、边界在哪里”。
- 产品架构回答“由什么组成、能力如何工作、未来如何演进”。
- 应用集成回答“如何通过协议和 API 使用或集成”。
- 运维部署回答“如何安装、运行、升级、切换和恢复”，其中部署与运行职责分别由两份手册维护。
- 架构版本只描述对应版本的事实或明确规划，不混写当前状态。
- API 字段以 `应用集成/OpenAPI/warehouse.openapi.yaml` 为准；移动文档必须同步更新链接、嵌入路径和构建命令。
