# 加密目录

本文定义 Warehouse Web 前端当前加密目录能力的事实源、缓存边界和删除后重建行为。

## 定位

加密目录是浏览器端加密能力。Warehouse 服务端只存储目录、文件和 marker 文件，不理解目录密钥，也不把“是否加密”写成后端目录属性。

目录是否为加密目录，以该目录下的 `.warehouse-crypto.json` 为事实源。前端发现该 marker 后，把目录路径注册到当前页面会话的加密根缓存，并据此决定上传前加密、下载后解密和 UI 标识。

## Marker 文件

加密目录根下固定存在：

```text
.warehouse-crypto.json
```

当前 marker 描述：

- `version`：元数据版本，目前为 `1`。
- `encrypted`：固定为 `true`。
- `cipherSuite`：目录使用的对称加密套件。
- `passwordSource`：密码来源，支持 `wallet`、`manual`、`wallet+password`。
- `createdAt`：marker 创建时间。

Web 文件列表会隐藏该 marker，不作为普通文件展示。

## 前端缓存

前端维护两个页面会话级缓存：

- `encryptedDirectoryRoots`：当前已发现的加密目录根。
- `encryptedDirectoryMetadata`：对应根目录的 marker 元数据。

额外密码只缓存在 `sessionStorage`，按加密目录根路径索引。刷新页面后内存缓存会重新从 WebDAV `PROPFIND` 和 marker 文件发现；额外密码缓存遵循浏览器 session 生命周期。

## 删除与重建

删除加密目录后，服务端会把整个目录移动到 `.recycle`，原路径下的 `.warehouse-crypto.json` 也会一起离开原目录。因此后端不会让同名新目录天然继承旧加密属性。

前端必须在删除成功后同步注销相关缓存：

- 删除某个加密根时，移除该根的 `encryptedDirectoryRoots`、`encryptedDirectoryMetadata` 和密码缓存。
- 删除某个父目录时，移除其下所有加密根缓存。
- 重新创建同名普通目录成功后，防御性清理同路径旧加密根缓存。
- 重新创建同名加密目录时，写入新的 `.warehouse-crypto.json`，再注册新的加密根缓存。

这样可以避免“加密目录删除后，重新创建同名普通目录仍被前端识别为加密目录”的误判。

## 操作边界

- 当前不支持直接重命名加密目录根；需要新建目录后迁移内容。
- 当前不支持把普通文件或目录直接移动进加密目录。
- 当前不支持把加密目录中的文件或目录直接移出到普通目录。
- 当前不支持在不同加密目录之间直接移动文件或目录。
- 加密目录文件不支持公开分享和定向分享；需要先解密导出后再按普通文件处理。
