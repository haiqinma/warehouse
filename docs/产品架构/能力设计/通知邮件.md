# 通知与邮件

本文定义 Warehouse 通知能力与 Node 邮件发送能力的边界。

## 定位

Warehouse 只负责判断业务事件、生成站内通知和组织邮件模板数据，不直接连接 SMTP，也不维护邮件模板渲染逻辑。

邮件发送统一交给 YeYing Node：Warehouse 通过 Node Pusher 事件接口发布通知事件，Node 根据通知、收件人身份、邮件偏好和邮件模板完成邮件投递。

## 发送链路

1. Warehouse 在本地创建或更新站内通知。
2. 如果事件需要邮件通知，Warehouse 以 Pusher app 身份向 Node 发送签名事件。
3. Node 持久化通知，并根据 `recipients` 解析身份邮箱凭证。
4. Node 按 `payload.emailTemplateId` / `payload.templateId` 优先选择邮件模板；没有显式模板时再按 `source + type` 匹配。
5. Node 邮件发送任务负责实际邮件投递、重试和失败记录。

## 配置

Warehouse 侧只保留配置文件入口，不再通过环境变量维护另一套邮件发送配置。

```yaml
email:
  node_email_enabled: true
  node_url: "https://identity.yeying.pub"
  pusher_app_id: "warehouse"
  pusher_key: "pk_xxx"
  pusher_secret: "ps_xxx"
  request_timeout: 10s
  quota_warning_template_id: "warehouse-storage-quota-warning"
```

其中：

- `node_email_enabled`：是否启用 Node 邮件投递。
- `node_url`：Node 服务地址。
- `pusher_app_id` / `pusher_key` / `pusher_secret`：Node 为 Warehouse 分配的 Pusher 应用凭据。
- `quota_warning_template_id`：存储额度告警通知显式使用的邮件模板 ID。

## 事件 Payload

存储额度告警通知应显式带模板 ID，避免依赖 `source + type` 的弱匹配：

```json
{
  "emailTemplateId": "warehouse-storage-quota-warning",
  "appName": "Warehouse",
  "unit": "MiB",
  "usedStorage": "274.62",
  "storageQuota": "300.00",
  "remainingStorage": "25.38",
  "overageStorage": "0.00",
  "usagePercent": "91.54",
  "accountId": "did:yeying:wid_abc"
}
```

当前代码会在用户存储额度告警触发时发布 `warehouse.storage.quota.warning` 事件，并显式携带 `warehouse-storage-quota-warning` 模板 ID。`usedStorage` 表示当前已用空间，`storageQuota` 表示存储配额，`remainingStorage` 表示剩余空间，`overageStorage` 仅在已超额时大于 0，`usagePercent` 表示已用比例。展示单位按配额大小选择：小于 1GiB 的配额使用 MiB，其它使用 GiB，避免低配额场景被两位小数压缩到难以判断。`accountId` 优先使用登录时保存的 YeYing Identity DID；仅在用户尚未绑定 DID 的历史数据场景下，才使用钱包地址作为 Node 可解析的通用 account。

## 边界

- Warehouse 不再直接实现 SMTP 发送、TLS 连接、邮件 From、邮件 HTML 模板渲染。
- 邮件模板配置、邮件渠道配置、发送重试、发送失败记录由 Node 负责。
- Warehouse 只在本地事件已成立时发布 Node 通知事件；Node 不反向决定 Warehouse 的业务状态。
- 邮箱验证码登录仍保留本地验证码状态机，但实际邮件验证码能力应收敛到 Node Identity 邮箱验证流程；Warehouse 不回退到本地 SMTP。
